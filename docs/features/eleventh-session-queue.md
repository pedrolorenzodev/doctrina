## UI rules for tonight (Pedro has been burned by agents that skipped these)

1. **Everything that moves is smooth, and you measure it per frame** (a rAF sampler, or a ResizeObserver created after the app's own; never a JS read in the middle of a frame): what appears, what disappears, and everything that shifts because of it (content above and below). No abrupt movement. Use the design system's curves and durations (DESIGN «Motion»: `ease-move`, `ease-reveal`, `ease-standard`, the 150 / 200 / 260 / 300 ms patterns), fade out completely, respect `prefers-reduced-motion` (instant). Reuse the existing motion helpers (`branch-motion.ts`, `fold-box.ts`, `flipBlocks`, `scrollToY`) before inventing one.
2. **Design system first.** Tokens from `@theme`, no arbitrary Tailwind values (lint rejects them: add a named token or an `@utility`), `npm run components <word>` before writing a component, hover / focus / active / disabled states on everything clickable, centred text in buttons, 44 px touch targets only under `pointer-coarse`, light and dark, widths 360 / 390 / 768 / 1440.
3. **An approved artifact is the specification, to the letter** (Pedro's saved notes in the feature doc included). **Measure it**: Playwright rects of every element at each width and state, its hover and pressed states, and read its script for behaviour; write the numbers in the block's checklist, measure the build the same way and compare number by number. Where the artifact contradicts or lacks something in the design system, adapt it faithfully to the design system and say so in the report. Where it is old-version UI, take its structure and copy and build it in the current look.
4. **No artifact, or no precise definition → the main rule applies:** publish a private proposal Artifact with live demos (2–4 options, what exists today beside them, what is discarded and why, the AI-slop list). Because Pedro cannot choose tonight, **build your own recommended option as its own provisional block** (the commit message says so, DECISIONS «to confirm», a one-line revert path) and continue. Never leave a UI block half done.
5. Links and buttons of an approved design are built even if inert (a `TODO` at the call site), never hidden. Comments only `TODO` or lint silencers (plus the one-line guard exception in AGENTS). Code, docs, names and commits in English; site content bilingual; Pedro reads Spanish (Rioplatense), brief.
6. After each block: `npm run typecheck`, eslint and prettier on the touched files, the specs in `e2e/` against a **production build** (`npm run build`; Playwright then starts `next start -p 3100`; dev servers make timing specs fail on hydration), screenshots, and a brief self-review against the block's checklist; fix before moving on. After a big block or several blocks: a detailed independent review (one Sonnet subagent at a time, `AGENTS.md` rule 13, memory `one-subagent-at-a-time`) on screenshots and code, then fix what it finds. Do not build while a suite runs. Timing specs fail under machine load (GitLens `gk` processes): repeat them alone with `--repeat-each` before calling a defect; the specs known to be flaky or red on a clean HEAD are listed in the feature doc `tenth-session-queue.md`, T13.

- Keep a morning index `docs/features/eleventh-session-commits.md`: per block its kit number, the commit message (English, Conventional Commits, ≤ 72 characters, no body, no attribution), the plain add-and-commit command with EVERY touched file (Pedro's AGENTS rule: file list plus ready-to-paste command), its dependencies on other blocks, and a one-line «what to check».
