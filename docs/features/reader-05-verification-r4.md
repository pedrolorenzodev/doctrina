## Verdict: PASS WITH FIXES

Visual geometry is very close to the proposal (strip, picker button, picker list, A− A+, action buttons all match to the pixel), there are no console errors, no failed requests and no horizontal overflow at any size. One real keyboard defect (D1) makes the picker's options unreachable when it is opened with Enter or Space, and there are three medium defects (D2 arrival jump, D3 sheet covers the tapped verse, D4 column squeezed at 1024–1180).

## Defects, by severity

**D1 (high, keyboard) The picker's options are unreachable when it is opened with Enter or Space.**
`src/features/reader/translation-picker.tsx` line 152 (`onClick={() => (open ? closeList(false) : openList(false))}`): Enter/Space produce a click, so `focusSelected` is false and focus stays on the button. Then line 121–123: ArrowDown/ArrowUp call `openList(true)`, which returns at line 97 (`if (!trigger || open) return`), so nothing moves; the options have `tabIndex=-1`, so Tab skips the list and closes it (line 141 is only reached from inside). Measured: Enter on button → ArrowDown, ArrowDown → focus still on the button. Fix: in the click handler pass `event.detail === 0` as `focusSelected`; and in `onButtonKeyDown`, when already open, focus the selected option instead of returning.

**D2 (medium) Arrival jump: the verse first lands behind the sticky strip, then the page jumps 47 px.**
Measured at 1440 on `/es/biblia/juan/6#v-53`: top 80.4 px at first paint (under the strip, whose bottom is 107), mark starts at +190 ms, then at ≈ 220 ms scrollY 4142 → 4095 and the verse top becomes 127.4. Cause: `src/features/reader/reader-strip.tsx` lines 27–39 set `--spacing-scroll-offset` (71 px) only after hydration; until then `globals.css` line 202 (24 px) feeds `scroll-padding-top` (line 1082). Fix: ship the real value in CSS for the chapter page (a class on the reader wrapper with 71 px ≥ 640 px and 63 px below), keep the effect only as a correction.

**D3 (medium, phone and tablet) The half sheet hides the verse that was just tapped.**
At 390x844 the sheet starts at y 405; a verse tapped below that is covered (screenshot `s10-sheet-390-top.png`). The proposal scrolls the selection above the sheet (`fuente.js` line 464: limit = sheet top − 16). `reader-body.tsx` `select`/`VersePanel` have no such scroll. Fix: after opening below 1024 px, scroll by `bottom − (sheetTop − 16)` if positive, capped so the verse top stays under the strip; instant under reduced motion.

**D4 (medium, 1024–1180 px) The reading column collapses when the panel opens.**
`globals.css` `side-panel-room` (line 887) sets padding-right to panel + 24 (404). At 1024 the title column is 284 px wide (verses 308), at 1100 it is 360, at 1280 540. DESIGN says panel + 48 and a breakpoint of 1100, with the sidebar open; with the 272 px sidebar the column is under 340 px from 1024 to about 1160 px. Fix: raise the column layout to a wider breakpoint (for example `xl`, 1280) and use the sheet below, or hide the right-hand padding of the strip and column; at minimum decide and record it in DECISIONS.

**D5 (low-medium) The copied citation contains a no-break space.** `reader-body.tsx` lines 56–65: `nbspBeforeDigits` is applied to the reference that feeds both the panel title and the citation, so the clipboard gets `Juan 6:7 (RV1909)` (U+00A0). Pasted into search or a plain document it does not match «Juan 6:7». Fix: build the citation from the unmodified reference (or replace U+00A0 with a space in `citation`).

**D6 (low) The copied label shifts its neighbour 50 px.** `src/components/ui/copy-button.tsx` line 36 swaps the text: «Citar» 52 px becomes «Cita copiada» 102 px and «Copiar enlace» moves from x 1129 to 1179. Fix: stack both labels in one grid cell (the hidden one `invisible`) so the width is the larger of the two.

**D7 (low) Two cosmetic flaws in the picker's Despliegue (shared `src/lib/branch-motion.ts`).** Line 51 animates to `list.scrollHeight` (padding box, 295) but the final border-box height is 297, so the last frame snaps 2 px. Lines 75–80 animate to `0px` on a box with padding and border, so the height bottoms out at 14 px for about 40 ms (an empty bordered strip, rows already at opacity 0) and then pops to 0. Fix for the picker: animate from/to the border-box height and put the padding on an inner wrapper, or animate `clip-path`/`max-height`; the tree sidebar is unaffected because its `ul` has no padding or border.

**D8 (low) Smaller deviations from DESIGN, all measured.**
- L1: panel and sheet use the shared `panel-motion` (`globals.css` line 872): 200 ms for opacity and translate; DESIGN asks 260 ms `ease-move` for the translate.
- L2: panel header 49 px (57 on touch) vs 56 px; width 380 vs the proposal's 400 (known token); body padding-top 18 vs 20.
- L3: `CopyButton` puts `role=status` inside the `<button>`: the accessible name becomes «Cita copiada Cita copiada» for 1.6 s and the live region is part of the control. Move the status outside the button.
- L4: the listbox contains plain text nodes (group heads have `role=presentation`), which axe may flag as an invalid listbox child; use `role=group` with `aria-label`.
- L5: A− A+ are 44 px high but 36 px wide on touch.
- L6: the verse button's accessible name is the whole verse text, with the verse number as a separate text node; one-line verses have a 26 px touch height (above WCAG 2.2's 24 px minimum, below DESIGN's 44).
- L7: the arrival lands at 127 px (desktop) and 115 px (phone), DESIGN says about 140.
- L8: numbering note copy says «pasa con varios Salmos» on Juan chapters.
- Picker flip-up code is unreachable in practice (the strip is sticky at the top, so `above` is always small); harmless but dead.
