## Procedures learned (do not relearn)
- **Never edit the real working tree while a kit has unapplied blocks** (the kit overwrites listed files). Build servers from a clone (`cp -cR`, 25 s). Duplicates for blocks: `cp -cR ~/Desktop/dev/doctrina ~/Desktop/dev/doctrina-ai-<name>`; ports via `E2E_PORT`.
- Merging a duplicate: list its changed files with `git status` in it, copy by explicit lists **per owner** (a loop over duplicates let stale stubs overwrite LIM's files once), compare against the real repo's history for conflicts, three-way patch only where both changed (`diff -u base theirs | patch -N ours`), `npm run verify` and the relevant checks, then give Pedro explicit-file commit commands.
- Kit apply always with explicit numbers: `cd ~/doctrina-commit-kit && ./apply.sh <numbers>`.
- Secrets: never print `.env.local` tails; a past INT run printed the tail of `AI_EVAL_SECRET` (rotating it is optional, low impact). `.env.local` must end with a newline before appending.
- Keyword router trap: `routeQuestion` swallowed free text (see the 2026-11-08 decision).
